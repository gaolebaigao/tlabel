## 1. 概述

### 1.1 背景

TLabel v0.13.0/v0.13.1 已经建立了 Motor Primitive 标注系统（22种 T-Rex primitives）和触觉事件（events）基础数据结构。v0.14.0 的核心目标是**打通"视触觉→力推断→Primitive标注"的完整工作流**，让用户能从一个无力的视触觉传感器数据出发，自动完成力推断、事件检测、Primitive 预标注，最终导出带完整元数据的数据包。

### 1.2 设计原则

| # | 原则 | 含义 |
|---|------|------|
| P1 | **直写不转换** | Adapter 输出的力分布数据直接写入 tlabel 标准字段，规则引擎直接从标准字段提取物理量判定 primitive。tlabel 字段既是输入格式也是存储格式。 |
| P2 | **辅助不权威** | 规则引擎的定位类似 Grammarly 预标注，不是权威分类器。所有自动标注都带 source + confidence。 |
| P3 | **低置信留空** | 低置信度的标注留空给用户手动标注，宁可少标不可错标。 |
| P4 | **内置+扩展** | 内置默认 7 种物理含义明确的 primitive（从 T-Rex 22 种中选取），同时支持用户自定义扩展。 |
| P5 | **UI 整合不新增 Tab** | 在标注 Tab 中整合 primitive 预标注和事件可视化，不新增独立 Tab。 |

### 1.3 完整用户工作流

```
导入力数据 → 选择 taxonomy → 自动预标注(带 confidence)
    → 用户审核补标 → 导出完整数据包(含 source/confidence 元数据)
```

## 5. Taxonomy 系统设计

### 5.1 内置默认 Primitive 子集

#### 选取依据

从 T-Rex 22 种 Motor Primitive 中选取时，考虑以下标准：

| 标准 | 权重 | 说明 |
|------|------|------|
| 力信号特征清晰度 | 40% | 该 primitive 在力/形变时间曲线上是否有明确的特征模式 |
| 物理含义明确性 | 30% | 用户（标注者）能否直观理解该动作的物理含义 |
| 视触觉可区分性 | 20% | 仅凭视触觉（形变、图像）信号能否区分该 primitive |
| 常见度 | 10% | 在典型机器人操作任务中出现的频率 |

#### 默认 7 种 Primitive

| # | Primitive | 力信号特征 | 选取理由 | 参考 Cutkosky |
|---|-----------|-----------|----------|---------------|
| 1 | `grasp` | 力上升 + contact 建立 + 形变增大 | 最基础操作，力特征最清晰 | Power Grasp (全手) / Precision Grasp (指尖) |
| 2 | `press` | 力快速上升 + 形变较小 + 无剪切力 | 垂直按压，特征与 grasp 区分度好 | — |
| 3 | `squeeze` | 力周期性波动 / 力持续增大 | 挤压动作，力特征独特 | — |
| 4 | `reach` | 无接触 + 低力 + 有位移 | 唯一非接触状态，容易区分 | — |
| 5 | `wrap` | 力稳定 + 接触面积增大 + 无剪切力 | 包裹动作，力趋于稳态 | — |
| 6 | `wipe` | 剪切力显著 + 横向运动 + 力波动 | 有明确剪切力信号 | — |
| 7 | `lift` *(备选)* | 力先升后降 + 位移变化 | 提起动作，力先增后减 | — |

> **说明**: 默认选取前 6 种（grasp, press, squeeze, reach, wrap, wipe），`lift` 作为第 7 种备选。实际实现中默认启用全部 7 种。

#### 与 PRIMITIVE_PRESETS (22种) 的兼容

```
PRIMITIVE_PRESETS (22种, 不可修改)
├── DEFAULT_PRIMITIVE_SUBSET (7种, 默认启用)
│   ├── grasp
│   ├── press
│   ├── squeeze
│   ├── reach
│   ├── wrap
│   ├── wipe
│   └── lift (备选, 默认启用)
├── 其余 15 种 (用户可通过 taxonomy 扩展启用)
│   ├── fold, cut, insert, peel, assemble, extract,
│   ├── twist, shake, dispense, disassemble, pour,
│   ├── open, close, screw, unscrew
│   └── ... (用户自定义的也可以放这里)
└── 用户自定义 (通过 taxonomy.register() 添加)
    └── 可以是全新的 primitive 名称
```

**兼容性保证**:
- `PRIMITIVE_PRESETS` 列表不变，`PrimitiveAnnotation` 构造函数仍检查 `name in PRIMITIVE_PRESETS`
- 用户自定义的 primitive 通过 `taxonomy.register()` 添加后，会同步注册到 `PRIMITIVE_PRESETS` 的运行时扩展集合中
- `DEFAULT_PRIMITIVE_SUBSET ⊂ PRIMITIVE_PRESETS`，保证默认 taxonomy 的 primitive 全部合法

function drawPrimitiveTrack() {
  const canvas = document.getElementById(tid + '-primitive-track');
  if (!data.primitive_annotations || data.primitive_annotations.length === 0) {
    canvas.style.display = 'none';
    return;
  }
  canvas.style.display = 'block';
  
  const ctx = canvas.getContext('2d');
  const W = canvas.width, H = canvas.height;
  ctx.clearRect(0, 0, W, H);
  
  const frames = data.frames || [];
  const totalFrames = frames.length;
  if (totalFrames === 0) return;
  
  // 绘制每个 primitive 区间
  for (const ann of data.primitive_annotations) {
    const x1 = (ann.start_frame / totalFrames) * W;
    const x2 = (ann.end_frame / totalFrames) * W;
    const color = PRIMITIVE_COLORS[ann.primitive_name] || '#D5D8DC';
    
    ctx.fillStyle = color;
    ctx.fillRect(x1, 2, Math.max(x2 - x1, 2), H - 4);
    
    // 标注名称 (如果区间足够宽)
    if (x2 - x1 > 30) {
      ctx.fillStyle = '#fff';
      ctx.font = '9px sans-serif';
      ctx.fillText(ann.primitive_name, x1 + 3, H / 2 + 3);
    }
  }
  
  // 置信度可视化: 低置信度区间加斜线纹理
  for (const ann of data.primitive_annotations) {
    if (ann.confidence < 0.5) {
      const x1 = (ann.start_frame / totalFrames) * W;
      const x2 = (ann.end_frame / totalFrames) * W;
      ctx.strokeStyle = 'rgba(0,0,0,0.2)';
      ctx.lineWidth = 1;
      for (let x = x1; x < x2; x += 6) {
        ctx.beginPath();
        ctx.moveTo(x, 0);
        ctx.lineTo(x + H, H);
        ctx.stroke();
      }
    }
  }
}

## 附录 B: 设计决策记录

### D1: 为什么不新增 "Primitive" Tab？

**决策**: 在标注 Tab 中整合，不新增 Tab。

**理由**:
1. Primitive 标注本质上是帧级标注的延伸，与时间轴、帧详情在同一上下文中操作更高效
2. 用户工作流是 "看帧 → 判断 → 标 primitive"，切换 Tab 会打断流程
3. 可折叠设计保证不使用时不占空间，保持界面简洁

### D2: 为什么 taxonomy 默认 7 种而不是 22 种？

**决策**: 默认 7 种，Full T-Rex 22 种作为可选项。

**理由**:
1. 22 种中很多 primitive 在力信号上难以区分（如 screw vs unscrew）
2. 7 种覆盖了最常见的操作类型，物理含义明确
3. 减少预标注的混淆，提高 precision
4. 用户可以按需扩展到 Full 22 种

### D3: 为什么 force_estimator 的推断结果直写 tlabel_v2？

**决策**: 直写 `tlabel_v2["force_magnitude"]`，不新增中间字段。

**理由**:
1. **P1 直写不转换** 原则：减少数据流层次，adapter 输出 = 存储格式 = 规则引擎输入
2. 在 `sensor_specific` 中记录推断元数据，保留溯源能力
3. 规则引擎不需要关心力数据是真实测量还是推断的，只需读 `tlabel_v2["force_magnitude"]`
4. 推断来源的区分体现在 primitive 标注的 source 标记上 (`ai_predicted_estimated`)
