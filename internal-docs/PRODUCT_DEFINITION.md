## 1. 产品定位

### 一句话定义
**触觉数据标注的学术标准工具** —— Python SDK，面向机器人研究者，提供触觉数据的加载、特征提取、动作分段（Primitive标注）、质量评估和标准化合规能力。

### 核心价值
1. **定义标准**：通过22维统一特征空间和T-Rex 22种Primitive，建立触觉数据的通用词汇表
2. **降低门槛**：让研究者能快速上手触觉数据处理，不需要从零写解析代码
3. **推动标准化**：通过开源+论文引用+标准合规，成为触觉数据领域的事实标准

### 与TLabel Web的关系
- **学术版（本SDK）** = 引擎，做算法+标准+生态
- **Web版（tlabel-web）** = 产品，做协作+可视化+商业化
- **关系**：学术版定义标准，Web版实现标准；学术版做底层能力，Web版做上层应用

| 维度 | 学术版（本SDK） | Web版 |
|------|----------------|-------|
| **形态** | `pip install tlabel` | Web SaaS平台 |
| **面向谁** | 机器人研究者（PhD/RA） | 工业质检用户 + 不想写代码的用户 |
| **核心能力** | 算法+标准+生态 | 协作+可视化+商业化 |
| **商业模式** | 开源免费，积累用户+论文引用 | 付费SaaS，按seat收费 |
| **项目资料** | `牛宿科技/tlabel-repo/` | `牛宿科技/tlabel-web/` |

## 2. 目标用户

### 核心用户
| 用户类型 | 核心需求 | 使用场景 |
|---------|---------|---------|
| 机器人研究者（PhD/RA） | 快速处理触觉数据，验证算法，发表论文 | 实验室数据处理、论文复现、算法对比 |
| 触觉传感器厂商 | 提供数据格式支持，接入生态 | 写adapter，让用户能用他们的传感器 |
| 开源社区贡献者 | 扩展功能，适配新传感器 | 贡献代码，完善生态 |

- ❌ 标注员/外包团队（需要浏览器操作）
- ❌ 不想写代码的用户（需要可视化界面）

## 3. 核心功能架构

### 功能分层

```
┌─────────────────────────────────────────────────────────────┐
│  生态层（Ecosystem）                                         │
│  ├── 传感器插件市场（TDAP协议）                             │
│  ├── 仿真数据对接（Isaac Sim/MuJoCo/Genesis）              │
│  └── 标准制定（Tactile Annotation Schema）                 │
├─────────────────────────────────────────────────────────────┤
│  标准层（Standard）                                          │
│  ├── T-Rex 22种Primitive动作词汇表                          │
│  ├── 22维统一特征空间                                       │
│  ├── Taxonomy分类体系                                       │
│  └── 质量分级标准                                           │
├─────────────────────────────────────────────────────────────┤
│  能力层（Core Capabilities）                                 │
│  ├── 数据加载与解析（多传感器适配）                         │
│  ├── 特征提取（22维自动计算）                               │
│  ├── AI预标注（规则+统计→后续升级为深度学习）              │
│  ├── Primitive自动识别与手动修正                            │
│  └── 数据导出（JSON/CSV/RLDS/LeRobot）                     │
└─────────────────────────────────────────────────────────────┘
```

### 功能分配原则

**学术版负责的：**
- ✅ 底层算法（特征提取、Primitive识别、质量评估）
- ✅ 标准定义（Schema、Taxonomy、质量规则）
- ✅ 生态建设（传感器插件、仿真对接、格式标准）
- ✅ 数据格式（加载、解析、导出）

**Web版负责的（学术版提供API）：**
- ✅ 多人协作标注（任务分配、权限管理、质检流程）
- ✅ 可视化界面（时间线编辑器、波形显示、热力图）
- ✅ 商业化功能（项目管理、计费、导出报告）

## 5. 重点功能详细设计

### 5.1 仿真数据对接（v2.0，高优先级）

**目标**：让仿真器为真实数据自动打标签，标注员只做校对

**核心能力**：
1. **仿真数据导入**
   - 支持Isaac Sim、MuJoCo、Genesis、SAPIEN的输出格式
   - 自动解析仿真中的ground truth（接触点、接触力、滑移状态、物体位姿、形变）
   
2. **真值自动标注**
   - 仿真数据自带完美ground truth，无需人工标注
   - 自动生成Primitive标签、接触事件、质量指标

3. **Real2Sim2Real闭环**
   - 真实数据标注 → 校准仿真参数 → 仿真生成更多数据
   - 域自适应/域随机化训练，迁移到真实传感器数据

4. **主动学习**
   - 模型不确定的帧优先推送人工标注
   - 最大化每一次人工标注的信息增益

**技术路径**：
- Phase 1：支持Isaac Sim数据导入 + 真值提取
- Phase 2：支持MuJoCo/Genesis
- Phase 3：Real2Sim2Real闭环 + 主动学习

**商业价值**：
- 标注成本降低一个数量级
- 和戴盟/他山的数据闭环直接对接

### 5.2 传感器插件架构（v0.15已落地核心 → v2.0完善TDAP协议）

**目标**：不自己适配所有传感器，而是做插件架构+生态，让传感器厂商和社区自己写适配器

**v0.15已落地（核心能力）**：
- ✅ BaseAdapter抽象基类，统一接口规范
- ✅ 表驱动注册（`_ADAPTER_MODULES`字典），新增适配器只需一行注册
- ✅ 9个官方适配器 + 2个实时SDK适配器（PaXini GEN3 / Daimon DM-Tac骨架）
- ✅ Exporter插件架构，7种导出格式完全向后兼容

**v2.0待完善（TDAP协议标准化）**：
1. **TDAP协议（Tactile Data Adapter Protocol）**
   - 定义标准接口规范（对外发布，厂商/社区可独立开发）
   - 规定传感器数据如何被加载、可视化、特征提取、导出
   
2. **适配器SDK**
   - 提供Python/C++ SDK（目前为内部使用，需封装为对外发布）
   - 传感器厂商只需实现几个接口就能接入平台
   
3. **插件市场**
   - 官方维护主流传感器
   - 社区和厂商贡献长尾传感器
   
4. **内置标定工具**
   - 手眼标定、传感器-机器人TCP标定、多传感器时空标定

**已支持传感器（官方维护，11个适配器）**：

- 形成"买传感器 → 用TLabel标数据 → 训练模型"的标准链路

### 5.3 Tactile Annotation Schema（v2.0，高优先级）

**目标**：定义触觉数据的标准标注格式（类似COCO之于视觉），掌握话语权

**Schema结构**：
```
Tactile Annotation Schema (TAS)
├── 信号层标签（Signal Level）
│   ├── contact（接触开始/结束）
│   ├── slip（滑移发生）
│   ├── force（力大小、方向）
│   ├── deformation（形变）
│   └── temperature（温度）
├── 语义层标签（Semantic Level）
│   ├── material（材质：金属/塑料/布料/湿滑）
│   ├── object_category（物体类别）
│   ├── operation_intent（操作意图）
│   └── task_phase（任务阶段）
├── 事件层标签（Event Level）
│   ├── contact_start / contact_end
│   ├── slip_occurrence
│   ├── failure（抓取失败、掉落、碰撞过载）
│   └── success（任务完成、卡扣到位）
└── 元数据规范（Metadata）
    ├── sensor_model（传感器型号）
    ├── calibration_params（标定参数）
    ├── environment_condition（环境条件）
    └── timestamp（时间戳）
```

**推广路径**：
1. 开源Schema定义（JSON Schema + Python类型）
2. 构建标准评测集（用TLabel标注高质量开源触觉数据集）
3. 发表论文（引用TLabel + TAS）
4. 参与标准制定（对接工信部YDT 6770-2026具身智能基准测试标准、中国信通院数据标注标准）

**商业价值**：
- 成为事实标准 → 工具自然成为行业标准 → 生态锁定
- 光轮正在主导20项国家/行业标准，触觉数据标准目前是空的，窗口期6-12个月

## 7. 技术栈

### 核心依赖
- Python 3.8+
- NumPy、SciPy（数值计算）
- Pandas（数据处理）
- Matplotlib（可视化，可选）

### 测试
- pytest（单元测试）
- 覆盖率 > 80%

## 9. 风险与应对

| 风险 | 应对 |
|------|------|
| 大平台（戴盟/他山）自己做标注工具 | 保持中立，不绑定任何厂商；做他们"不愿做"的长尾传感器和学术场景 |
| 传感器技术路线收敛 | 插件化架构，新传感器只需写adapter；22维特征空间抽象确保核心不随硬件变化 |
| 市场太小（触觉领域小众） | 具身智能2026年数据规模化元年，触觉传感器装配率从10%→60%+，标注需求滞后6-12个月爆发，提前卡位 |
| Token不足，开发进度慢 | 优先做高ROI功能（仿真对接、插件架构）；低ROI功能推迟或交给社区 |
